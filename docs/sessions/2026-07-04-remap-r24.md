## What shipped

- `src/server/crystallize.js` — pure `remapComposites(circuits, toolSpecs)` +
  `successorFor(oldName, toolSpecs)`. The deterministic successor rule: an
  enabled GET whose name preserves the old name's segments **in order** and
  ends on the **same resource segment** (`get_api_users` → `get_api_v2_users`).
  Exactly one candidate → re-map (new circuit key, links' from/to renamed,
  composite identity + `seen` count intact). Zero or many → **dormant with a
  reason** — ambiguity is a reason, not a coin flip.
- A step the **user disabled** never gets re-routed around: dormant with
  "disabled by the user" (write-safety spirit: the human's choice outranks
  the organism's convenience).
- `src/server/stdio.js` wake-up block: applies re-maps to `manifest.labs`,
  logs an `audit` event per re-map (`composite re-mapped (R2.4): x → y`),
  records a `composite|<name>|dormant` failure lesson per sleeper, persists
  via the existing `mergeManifestKeySync` (labs + sparding), stderr only.
